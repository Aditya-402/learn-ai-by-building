A strange fact

Python is a slow language. Its own documentation says so. And yet, almost all of AI is built with it.

At most of my workshops, students ask me this.

  • Is AI Python?
  • Is Python AI?
  • Why not the other languages we already have, for AI?
  • What is so special about Python?

Good questions. And here is the puzzle inside them. Languages like C and Java run faster than Python.

Before you read on, decide. AI runs billions of calculations. Why would it pick the slower language? Hold on to your guess.

It reads like English

Let's start with the person, not the computer. Say you want the computer to say hello.

Python: one line

print("Hello")

Java: five lines

public class Hello {
  public static void main(String[] a) {
    System.out.println("Hello");
  }
}

Same job. Most of the Java lines are not about hello at all. Press ▶ Run, then change the word, and run it again.

Now, why does that matter for AI? Because AI work is not written from fixed rules. You start with an assumption. You run an experiment. You look at the results, and build on them. Then you go round again, many times.

How AI work really goes

start with an assumption → run an experiment → look at the results → build on them → and round again

Python reads close to plain English. You change one line, and run it again, straight away. So every try is quick. And in AI, quick tries matter most.

Readability counts
Python even has this written into its own rules, the Zen of Python: "Readability counts."

Who does the heavy work?

But we still have our puzzle. If Python is slow, who does all that heavy work?

Say you ride a scooter to college. You turn the key and twist the accelerator. That's all. Underneath, the engine does the hard work. You never touch it. And you still reach on time.

Python is your hand on the accelerator. C and C++ is the engine.

Python is your hand on the accelerator. You twist it, and the engine does the work. The engine is fast code, written in C and C++. On graphics cards, it is CUDA. The heavy maths runs there, not in Python.

This fast code, packed so that Python can call it, is what we call a library. NumPy and PyTorch are two of them.

Let's time it

Say a shop has ten million bills. Price times quantity, all added up. I asked an AI to do it two ways: a plain Python loop, and the same job handed to NumPy.

I ran it on my own laptop. An Intel Core i7, eleventh generation (i7-1185G7). 32 GB of RAM. Windows 11, Python 3.13, NumPy 2.2. No graphics card, only the processor. I ran each version five times, and took the middle one, what we call the median.

Same answer. Plain loop 1.16 s, NumPy 0.010 s. About a hundred times faster.

Same answer. About a hundred times faster, because the work moved out of Python, into C. So yes, Python is slow. But AI in Python is not.

Now try it yourself, right here. This page runs a smaller Python inside your browser, so it is slower than a laptop, and your numbers will differ. Look at the gap, not the seconds.

Key idea
Python on the outside. C on the inside.

How it became the language of AI

Python was not built for AI. Guido van Rossum started it in 1989, in the Netherlands, as a simple everyday language. And no, it is not named after the snake. It is named after a comedy show, Monty Python.

Then the tools came, one after another.

Each new tool made the next one easier to build. More people came, and built more tools. Many tools, and the people who build them: this is what we call an ecosystem.

The numbers

So where does Python stand today? Here are the numbers, checked in October 2026.

  • New AI projects on GitHub: nearly half are written in Python.
  • AI research code: out of every hundred papers that shared their code, about 62 used PyTorch. TensorFlow, just 2.
  • People learning to code: 72 in every hundred use Python. That is number one.

But is Python the most used language in the world? It depends who you ask.

  • TIOBE index (it counts web searches): number one.
  • Stack Overflow's developer survey: number four.
  • GitHub: number two.
Key idea
Python is not number one everywhere. But for AI, it is the first choice.

The honest cost

So far, the good side. Now, what does Python cost?

First, write your own loops over big data, and you feel the slowness. A hundred times, as we just saw.

Second, Python is not the answer for every job.

  • Android apps are mostly written in Kotlin.
  • Websites in your browser run on JavaScript.

From my own work

I have lived this myself. In 2019, I worked on a deep learning project in the automotive world. Cars with driver assistance, called ADAS, already had cameras as their eyes. We were building their ears.

Camera = eyes. Four microphone clusters, at the head and tail lamps = ears.

Because when you drive, you don't only see things that need your attention. You also hear them. A horn is a warning. A siren means an emergency, for someone.

We trained the model in Python. But to run it inside the car's controller, we wrote the libraries underneath in C, and flashed them in.

So, is AI Python? No. AI itself does not belong to any one language. Python wins for other reasons:

  1. It is easy to read, and easy to learn.
  2. It is open source.
  3. It has libraries for almost everything.
  4. A huge community keeps helping each other.

So use Python to build and try AI. And other tools, where the job needs them.

When AI writes the code

One last question. If AI writes the code anyway, does the language even matter?

In this year's Stack Overflow survey, Python came first as the language people use AI tools with. Just ahead of JavaScript. And the best known tests of AI coding are in Python.

So very often, the code AI hands you will be Python. And someone has to read it. Check it. And fix it, when it breaks.

That someone is you.

The takeaway

So, why Python for AI? Not for speed. Python only looks fast, because faster engines in C run under its hood. It wins because it is easy to read, and quick to try.

But this leaves you with a question. When AI hands you a Python program, can you read it?

Your homework

Count the lines, then mark the words

Ask any AI for a program that adds up your monthly expenses. Once in Python, and once in Java. Put them side by side.

  1. Count the lines of each.
  2. Mark every word you cannot explain.

Don't worry if you mark a lot. That list is where your learning starts.

One question for you: how many lines did each one take, and which one could you explain to a friend? And your guess from the start: was it right? Tell me under the video.
