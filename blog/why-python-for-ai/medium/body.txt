<p><a href="https://www.youtube.com/watch?v=e8wzQ9w9WdQ">https://www.youtube.com/watch?v=e8wzQ9w9WdQ</a></p><h3>A strange fact</h3><p>Python is a slow language, and <a href="https://docs.python.org/3/glossary.html">its own documentation says so</a>. Yet almost all of AI is built with it. At most of my workshops, students ask me about this.</p><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-python-for-ai/medium/workshop.png" alt="Students with their hands up: Is AI Python?"></figure><ul><li>Is AI Python?</li><li>Is Python AI?</li><li>Why not use the other languages we already have, for AI?</li><li>What is so special about Python?</li></ul><p>These are good questions, and there is a puzzle inside them. Languages like C and Java run faster than Python, while AI runs billions of calculations.</p><blockquote><b>Decide first:</b> Why would AI pick the slower language? Make your guess before you read on. The section "Who does the heavy work?" answers it.</blockquote><h3>It reads like English</h3><p>Let's start with the person, not the computer. Say you want the computer to print one word: Hello.</p><p><b>Python: one line:</b> print("Hello")</p><p><b>Java: five lines:</b> public class Hello {<br> public static void main(String[] a) {<br> System.out.println("Hello");<br> }<br>}</p><p>Both programs do the same job, but most of the Java lines have nothing to do with hello. Try the Python one: press Run, change the word on the line marked <code># edit here</code>, and run it again.</p><p><i>On <a href="https://aditya-402.github.io/learn-ai-by-building/blog/why-python-for-ai/">the original post</a>, every code block runs right in your browser. Here, copy it into any Python.</i></p><pre>print(&quot;Hello&quot;)    # edit here: change the word inside the quotes</pre><p>Why does that matter for AI? Because AI work is not written from fixed rules. You start with an assumption, run an experiment, look at the results and build on them. Then you go round again, many times.</p><p><b>How AI work really goes:</b> start with an assumption → run an experiment → look at the results → build on them → and round again</p><p>Python reads close to plain English, so you can change one line and run it again straight away. Every try is quick, and in AI, quick tries matter most.</p><blockquote><b>Readability counts:</b> Python even has this written into its own rules, <a href="https://peps.python.org/pep-0020/">the Zen of Python</a>: "Readability counts."</blockquote><h3>Who does the heavy work?</h3><p>That still leaves our puzzle: if Python is slow, who does all the heavy work?</p><p>Say you ride a scooter to college. You turn the key and twist the accelerator, and that is all you do. Underneath, the engine does the hard work, and you never touch it. You still reach on time.</p><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-python-for-ai/medium/scooter.png" alt="A scooter: Python is your hand on the accelerator, C and C++ is the engine"><figcaption>Python is your hand on the accelerator. C and C++ is the engine.</figcaption></figure><p>Python is your hand on the accelerator. You twist it, and an engine of fast code, written in C and C++, does the work. On graphics cards, that engine is CUDA. The heavy maths runs there, not in Python.</p><p>Fast code packed so that Python can call it is what we call a <b>library</b>. NumPy and PyTorch are two of them: NumPy's work is <a href="https://numpy.org/doc/stable/user/whatisnumpy.html">done by pre-compiled C code</a>, and <a href="https://arxiv.org/abs/1912.01703">most of PyTorch is written in C++</a>.</p><h3>Let's time it</h3><p>Say a shop has 10 million bills, and you want price times quantity, all added up. I asked an AI to write this two ways: a plain Python loop, and the same job handed to NumPy.</p><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-python-for-ai/medium/bills-laptop.png" alt="A stack of shop bills, times ten million · My laptop"></figure><p>I ran both on my own laptop, using only the processor, with no graphics card.</p><ul><li><b>Intel Core i7-1185G7 (11th generation), 32 GB RAM</b>: Windows 11, Python 3.13, NumPy 2.2; Each version run 5 times; the middle result (the <b>median</b>) kept</li></ul><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-python-for-ai/medium/bar-loop-bar-numpy.png" alt="Plain Python loop: 1.16 seconds · NumPy: 0.010 seconds"><figcaption>Same answer. Plain loop 1.16 s, NumPy 0.010 s: about 100 times faster.</figcaption></figure><p>Both gave the same answer, but NumPy was about 100 times faster, because the work moved out of Python and into C. So yes, Python is slow, but AI in Python is not.</p><h4>Try it: time it in your browser</h4><p><b>The goal:</b> see the gap between a plain loop and NumPy for yourself.</p><p><b>The steps:</b> press Run and wait a few seconds. Then, on the line marked <code># edit here</code>, make the number of bills smaller or bigger and run again.</p><p><b>Guess first:</b> with 10 times fewer bills, will the gap shrink, grow, or stay about the same?</p><pre>import time
import numpy as np

n = 1_000_000                       # edit here: the number of bills, try 100_000
price = [i % 500 + 10 for i in range(n)]
qty = [i % 5 + 1 for i in range(n)]

# 1. a plain Python loop
start = time.perf_counter()
total = 0
for i in range(n):
    total = total + price[i] * qty[i]
loop_time = time.perf_counter() - start

# 2. the same job, handed to NumPy (C underneath)
p = np.array(price, dtype=np.int64)
q = np.array(qty, dtype=np.int64)
start = time.perf_counter()
total_np = int(np.dot(p, q))
numpy_time = max(time.perf_counter() - start, 0.0001)

print(&quot;plain loop:&quot;, round(loop_time, 3), &quot;s&quot;)
print(&quot;NumPy:     &quot;, round(numpy_time, 4), &quot;s&quot;)
print(&quot;same answer:&quot;, total == total_np)
print(&quot;NumPy was about&quot;, round(loop_time / numpy_time), &quot;times faster&quot;)</pre><p><b>What you should see:</b> "same answer: True", and NumPy many times faster than the loop. This page runs a smaller Python inside your browser, so your seconds will differ from my laptop's. Look at the gap, not the seconds.</p><blockquote><b>Key idea:</b> Python on the outside. C on the inside.</blockquote><h3>How it became the language of AI</h3><p>Python was not built for AI. Guido van Rossum started it in 1989, in the Netherlands, as a simple everyday language. And no, it is not named after the snake: <a href="https://docs.python.org/3/faq/general.html">it is named after a comedy show</a>, Monty Python.</p><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-python-for-ai/medium/snake-comedy-tv.png" alt="A python snake, crossed out · A TV with a laughing face: a comedy show"></figure><p>Then the tools for AI arrived, one after another.</p><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-python-for-ai/medium/brick-numpy-brick-sklearn-brick-tensorflow-brick-pytorch.png" alt="NumPy, 2005 · scikit-learn, 2010 · TensorFlow, 2015 · PyTorch, 2016"></figure><p>Each new tool made the next one easier to build, so more people came and built still more tools. Many tools, together with the people who build them, form what we call an <b>ecosystem</b>.</p><h3>The numbers</h3><p>So where does Python stand today? Here are the numbers, checked in October 2026.</p><ul><li><b><a href="https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/">New AI projects on GitHub</a></b>: nearly half</li><li><b><a href="https://web.archive.org/web/20250609230938/https://paperswithcode.com/api/stats/?type=quarter&amp;from=2021-03-01&amp;to=2025-03-31">AI research papers that shared their code</a></b>: about 62 in 100 used PyTorch; TensorFlow just 2</li><li><b><a href="https://survey.stackoverflow.co/2025/technology">People learning to code</a></b>: 72 in 100 use Python, the most of any language</li></ul><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-python-for-ai/medium/pie-half-bar-pytorch-bar-tf-dots-72.png" alt="Nearly half · PyTorch: 62 of 100 papers · TensorFlow: 2 of 100 papers · 72 of 100 dots filled"></figure><p>But is Python the most used language in the world? That depends on who you ask. The <a href="https://www.tiobe.com/tiobe-index/">TIOBE index</a>, which counts web searches, puts it at number 1. Stack Overflow's developer survey puts it at number 4, and GitHub at number 2.</p><blockquote><b>Key idea:</b> Python is not number 1 everywhere. But for AI, it is the first choice.</blockquote><h3>The honest cost</h3><p>That is the good side. Now, what does Python cost?</p><p>First, when you write your own loops over big data, you feel the slowness: about 100 times, as the timing showed.</p><p>Second, Python is not the answer for every job. Android apps are <a href="https://developer.android.com/kotlin/first">mostly written in Kotlin</a>, and websites in your browser run on JavaScript.</p><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-python-for-ai/medium/devices.png" alt="A phone app and a browser window"></figure><h3>From my own work</h3><p>I have lived this myself. In 2019, I worked on a deep learning project in the automotive world. Cars with driver assistance, called ADAS, already had cameras as their eyes, and we were building their ears.</p><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-python-for-ai/medium/adas-car.png" alt="A car with a camera behind the windscreen, microphone clusters at the lamps, and a siren behind"><figcaption>Camera = eyes. Four microphone clusters, at the head and tail lamps = ears.</figcaption></figure><p>When you drive, you don't only see the things that need your attention; you also hear them. A horn is a warning, and a siren means an emergency for someone.</p><p>We trained the model in Python. But to run it inside the car's controller, we wrote the libraries underneath in C and flashed them onto the chip.</p><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-python-for-ai/medium/train-to-chip.png" alt="Trained in Python on a laptop, runs in the car in C"></figure><p>So, is AI Python? No. AI itself does not belong to any one language. Python wins for other reasons:</p><ol><li>It is easy to read, and easy to learn.</li><li>It is open source.</li><li>It has libraries for almost everything.</li><li>A huge community keeps helping each other.</li></ol><p>So use Python to build and try AI, and other tools where the job needs them.</p><h3>When AI writes the code</h3><p>One last question: if AI writes the code anyway, does the language even matter?</p><p>In this year's Stack Overflow survey, Python came first as <a href="https://survey.stackoverflow.co/2026/technology/data/languages">the language people use AI tools with</a>, just ahead of JavaScript. And the best-known tests of AI coding, such as <a href="https://arxiv.org/abs/2310.06770">SWE-bench</a>, are in Python.</p><p>So very often, the code an AI hands you will be Python. Someone has to read it, check it, and fix it when it breaks. That someone is you.</p><h3>The takeaway</h3><ol><li>Python is not chosen for speed. It only looks fast, because engines written in C run under its hood.</li><li>It wins because it is easy to read and quick to try, and AI work is many quick tries.</li><li>AI does not belong to one language: Python to build and try, other tools where the job needs them.</li></ol><p>That leaves you with a question. When an AI hands you a Python program, can you read it?</p><h3>Your homework</h3><h4>Count the lines, then mark the words</h4><p>Ask any AI app for a program that adds up your monthly expenses, once in Python and once in Java.
