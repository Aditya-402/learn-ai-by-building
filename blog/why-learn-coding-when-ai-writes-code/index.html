A question students keep asking me

Of late, students keep asking me this one question. "Sir, AI writes code now. Should I still learn coding?"

That's a very nice question. Let me answer it with one small test.

Say you and your friends go out for dinner. The rule is simple. Everyone pays an equal share. Say an AI gives you these two programs. One of them is wrong.

Program A

share = bill ÷ friends

Program B

share = 500

Stop here, and find the wrong one. Hold on to your answer.

First, let's be fair to the AI

You ask it for a program. In ten seconds, you get it. It runs. Many times, it is even correct.

But it writes both right and wrong things. And the wrong ones don't always look wrong.

Here are both programs. Press ▶ Run. The bill is two thousand rupees, and there are four friends.

A says five hundred. B says five hundred. Both correct, right?

The reveal: it ran, and it was wrong

Now a fifth friend joins. Same bill. Change friends = 4 to friends = 5, and run it again.

A says four hundred. B still says five hundred. Did you find it? B never followed the rule. It only matched last week's answer.

No crash. No error. Still wrong.
Nothing crashed. No error came. The program ran perfectly, and it was still wrong. Someone at that table pays from his own pocket, and nobody knows why.

And the only person who can catch it is someone who can read those two lines.

The auto ride

Let's try to understand this in another way. Say you took an auto to go somewhere new. The driver takes a turn you have never seen. If you know the road, you ask him why. If you don't, you simply pay the meter.

Code is the same. If you cannot read the road, you will not notice the wrong turn.

Reading the code an AI wrote, and judging it line by line, is what we call code review.

So with Generative AI, your job does not disappear. It shifts. From typing the code, to reading it and judging it.

Agentic AI: the fresher

Now, Agentic AI goes one step further. An agent does not stop at writing code. It plans, picks a tool, acts, checks the result, and goes again.

So, if the AI can do all this on its own, do you need to know even less?

Say you joined a company as a fresher. You get a role, an objective, and some tools. That, effectively, is what an agent is.

Now tell me. Would any team lead give a fresher full access on day one, without checking the work? No, right? Someone who knows the job checks the work. With agents, that someone is you.

And to check the work, you must know the job yourself. This is what we call keeping a human in the loop.

What coding really trains

So what does knowing the job really mean? A program is a set of well defined instructions. Learning to code trains you to think in exact steps, with no ambiguity.

And that same skill makes your prompts sharp. A vague instruction gets you a vague program.

In a nutshell, the AI types faster than you. But you decide what is right.

True even if the AI becomes perfect
This does not depend on the AI being weak. Even if it writes perfect code one day, someone still has to say exactly what is needed. And someone has to judge whether it was done right.

The honest cost

Deciding what is right is a skill, and every skill has a cost. Learning to code takes time. You will fail many times. There is no shortcut around it, and I am not going to pretend there is one.

And not every problem needs code, or an agent. Start with the problem, then pick the tool. Fit for purpose thinking, not trend first thinking.

So, AI can write the code. But you still need to understand what that code is supposed to do, and whether it is correct.

Your homework

Read it, change it, predict it

Take one program that an AI wrote for you. Read it, line by line. Change one number. Predict the output, then run it. No program of your own yet? Use the one below: predict first, then press ▶ Run.

If your prediction was wrong, that is good. That is exactly where the learning starts.
