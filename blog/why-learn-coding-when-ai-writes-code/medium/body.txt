<p><a href="https://www.youtube.com/watch?v=hsvDCwUhs74">https://www.youtube.com/watch?v=hsvDCwUhs74</a></p><h3>A question students keep asking me</h3><p>Of late, students keep asking me one question: <i>"Sir, AI writes code now. Should I still learn coding?"</i> That's a very nice question, and one small test answers it.</p><p>Say you and your friends go out for dinner, and the rule is simple: everyone pays an equal share. An AI gives you two programs for it, and one of them is wrong.</p><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-learn-coding-when-ai-writes-code/medium/dinner4.png" alt="Four friends at dinner, and the bill on the table"></figure><p><b>Program A:</b> share = bill &#247; friends</p><p><b>Program B:</b> share = 500</p><blockquote><b>Decide first:</b> Which program is wrong, A or B? Pick one before you read on. The section "The reveal" answers it.</blockquote><h3>First, let's be fair to the AI</h3><p>You ask an AI for a program, and within 10 seconds you have it. It runs, and many times it is even correct.</p><p>But an AI writes both right and wrong code, and the wrong code doesn't always look wrong.</p><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-learn-coding-when-ai-writes-code/medium/bill2000.png" alt="The bill: 2,000 rupees"><figcaption>A bill of 2,000 rupees, shared by 4 friends.</figcaption></figure><h4>Try it: run both programs</h4><p><b>The goal:</b> see what each program says for tonight's dinner.</p><p><b>The step:</b> press Run. The bill is 2,000 rupees, and there are 4 friends.</p><p><b>Guess first:</b> what will each program say?</p><p><i>On <a href="https://aditya-402.github.io/learn-ai-by-building/blog/why-learn-coding-when-ai-writes-code/">the original post</a>, every code block runs right in your browser. Still wrong.:</b> Nothing crashed and no error came. The program ran perfectly, and it was still wrong. Someone at that table pays from his own pocket, and nobody knows why.</blockquote><p>The only person who can catch it is someone who can read those two lines.</p><h3>The auto ride</h3><p>Let's try to understand this another way. Say you took an auto to go somewhere new, and the driver takes a turn you have never seen. If you know the road, you ask him why. If you don't, you simply pay the meter.</p><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-learn-coding-when-ai-writes-code/medium/auto-route.png" alt="An auto-rickshaw with its meter &#183; Your usual way, and the turn you never saw"><figcaption>Know the road, and you ask why. Don't, and you pay the meter.</figcaption></figure><p>Code works the same way: if you cannot read the road, you will not notice the wrong turn.</p><p>Reading the code an AI wrote, and judging it line by line, is what we call <b>code review</b>.</p><p>So with Generative AI, your job does not disappear; it shifts, from typing the code to reading it and judging it.</p><h3>Agentic AI: the fresher</h3><p>Agentic AI goes one step further. An agent does not stop at writing code: it plans, picks a tool, acts, checks the result, and goes again.</p><p>So if an AI can do all of this on its own, do you need to know even less?</p><p>Say you joined a company as a fresher. You get a role, an objective and some tools. That, effectively, is what an agent is.</p><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-learn-coding-when-ai-writes-code/medium/fresher.png" alt="A fresher on day one: ID badge, laptop, a role, an objective, some tools"></figure><p>Would any team lead give a fresher full access on day one, without checking the work? No, right? Someone who knows the job checks the work, and with agents, that someone is you.</p><figure><img src="https://aditya-402.github.io/learn-ai-by-building/blog/why-learn-coding-when-ai-writes-code/medium/teamlead.png" alt="A team lead checking the fresher&#x27;s work, line by line"></figure><p>To check the work, you must know the job yourself. This is what we call keeping a <b>human in the loop</b>.</p><h3>What coding really trains</h3><p>So what does knowing the job really mean? A program is a set of well-defined instructions, and learning to code trains you to think in exact steps, with no ambiguity.</p><p>That same skill makes your prompts sharp, because a vague instruction gets you a vague program.</p><p>In a nutshell, the AI types faster than you, but you decide what is right.</p><blockquote><b>True even if the AI becomes perfect:</b> This does not depend on the AI being weak. Even if it writes perfect code one day, someone still has to say exactly what is needed, and someone has to judge whether it was done right.</blockquote><h3>The honest cost</h3><p>Deciding what is right is a skill, and every skill has a cost. Learning to code takes time, and you will fail many times. There is no shortcut around it, and I am not going to pretend there is one.</p><p>Not every problem needs code, or an agent, either. Start with the problem, then pick the tool: fit-for-purpose thinking, not trend-first thinking.</p><h3>The takeaway</h3><ol><li>An AI writes code fast, and it writes both right and wrong code. The wrong code can run without a single error.</li><li>Your job shifts from typing the code to reading it and judging it, and with agents, to checking their work.</li><li>Learning to code trains you to think in exact steps, so you can say what is needed and judge what you get.</li></ol><p>So an AI can write the code. But you still need to understand what that code is supposed to do, and whether it is correct.</p><h3>Your homework</h3><h4>Read it, change it, predict it</h4><p><b>The goal:</b> practise reading code an AI wrote, before you trust it.</p><p><b>The steps:</b> take one program that an AI wrote for you, and read it line by line.
